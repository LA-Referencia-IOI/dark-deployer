# Decoupled Infrastructure Architecture — Sandbox & Production

## Overview

In the **developer** profile, the entire dARK stack runs on a single machine.  
In **sandbox** and **production** profiles, the infrastructure is split across two dedicated servers:

| Server | Responsibility |
| ------ | -------------- |
| **Blockchain Server** | Hyperledger Besu node, smart-contract deployment, block explorer, IPFS + IPFS Cluster |
| **Application Server** | Admin API, Minter API, Resolver API, Store API, Dashboard |

This separation allows each tier to scale, be secured, and be maintained independently. The application services connect to the blockchain/IPFS tier over the private network — they do not run blockchain software themselves.

The application server reads `RPC_URL` and the IPFS endpoint from `.env` — these point to the blockchain server's IP/hostname. No local blockchain or IPFS process runs on the application server.

## Changes Required in dark-deployer

### 1. New `.env` variables

Add two variables per profile to declare whether the blockchain/IPFS tier is remote:

```ini
# ── SANDBOX PROFILE ──────────────────────────────────────────
# Leave blank to run blockchain/IPFS locally (developer default).
# Set to the blockchain server's address to skip local deployment.
SANDBOX_BLOCKCHAIN_HOST=
SANDBOX_IPFS_HOST=

# RPC endpoint exposed by the blockchain server
RPC_URL=http://<blockchain-server-ip>:8545

# IPFS API exposed by the blockchain server
SANDBOX_IPFS_API_URL=http://<blockchain-server-ip>:5001
SANDBOX_IPFS_CLUSTER_URL=http://<blockchain-server-ip>:9094
```

When `SANDBOX_BLOCKCHAIN_HOST` is set, `install.py` skips `install_blockchain()` on the application server.  
When `SANDBOX_IPFS_HOST` is set, `install.py` skips `install_dark_ipfs()` on the application server.

### 2. `install_profile()` guard logic

```python
def install_profile(prefix: str, env: dict) -> None:
    blockchain_host = env.get(f"{prefix}_BLOCKCHAIN_HOST", "").strip()
    ipfs_host       = env.get(f"{prefix}_IPFS_HOST", "").strip()

    if blockchain_host:
        print(f"[INFO] Blockchain is remote ({blockchain_host}) — skipping local install.")
    else:
        install_blockchain(prefix=prefix, env=env)

    install_core_lib(prefix=prefix, env=env)
    install_core_admin_api(prefix=prefix, env=env)

    if ipfs_host:
        print(f"[INFO] IPFS is remote ({ipfs_host}) — skipping local install.")
    else:
        install_dark_ipfs(prefix=prefix, env=env)

    install_dark_store_api(prefix=prefix, env=env)
    install_core_resolver_api(prefix=prefix, env=env)
    install_single_component(name="MINTER", prefix=prefix, env=env)
    install_dashboard(prefix=prefix, env=env)
```

### 3. Integration env files

Each service receives an `.env.integration` file generated by `install.py`. In the decoupled setup, `RPC_URL` and IPFS endpoints in those files must point to the blockchain server's IP, not `localhost`. No other change is needed in the service Dockerfiles or compose files.

## Deployment Flow

### Phase 1 — Blockchain Server

Run `install.py` on the blockchain server with a profile that sets only the blockchain/IPFS components (set all application-service URLs to empty):

```bash
# On blockchain server
cp .env.example .env
# Set TYPE=sandbox, fill blockchain/IPFS repo URLs, leave service URLs empty
python3 install.py
```

After completion, note:
- `RPC_URL` written into `.env` by `dark-env` setup
- IPFS API address (`http://<ip>:5001`)
- IPFS Cluster address (`http://<ip>:9094`)
- Deployed contract addresses from `dark-dapp/deployed_contracts.ini`

### Phase 2 — Application Server

```bash
# On application server
cp .env.example .env

# Fill in connection to the blockchain server:
# SANDBOX_BLOCKCHAIN_HOST=<blockchain-server-ip>
# SANDBOX_IPFS_HOST=<blockchain-server-ip>
# RPC_URL=http://<blockchain-server-ip>:8545
# SANDBOX_IPFS_API_URL=http://<blockchain-server-ip>:5001
# SANDBOX_IPFS_CLUSTER_URL=http://<blockchain-server-ip>:9094
# MASTER_WALLET_ADDRESS / MASTER_PRIVATE_KEY from Phase 1

python3 install.py
```

`install.py` detects the remote hosts and skips local blockchain/IPFS deployment, installing only the application services.

---

## Network Requirements

The application server must be able to reach the blockchain server on these ports:

| Port | Protocol | Purpose |
| ---- | -------- | ------- |
| 8545 | HTTP | Besu RPC endpoint |
| 5001 | HTTP | IPFS API |
| 9094 | HTTP | IPFS Cluster API |

These ports should be firewalled to allow only the application server's IP. They must not be publicly exposed.
